## 0. 这份文档管什么 / 不管什么

**管**：agent 与用户之间那条对话流里的一切 —— 每种「对话里会发生的事」长什么样、处在什么状态、怎么动、按钮多大。

**不管**：agent 的后端循环（`electron/ai/agentLoop.ts`）、工具 schema、画布节点视觉（主文档 §4/§5）、时间轴。

**为什么必须单独成章**：B5 要落 17 种对话形态，而设计系统主文档里此前**没有任何 agent 章节**（grep 只命中付费确认弹窗与 logo）。没有依据就动手 = 每个形态各写各的，正是 `CanvasAssistantPanel`(770 行) / `CreationAiPanel`(800 行) 长成今天这样的原因。

## 1. 一句话主张

> **对话流是施工现场的实时监控，不是聊天记录。**

推出三条能判对错的原则：

**① 原位更新，不追加。**
聊天记录只能往下追加，说过的话不会变；agent 干活不是。「排队第 3 位」→「进行中 3/5」→「完成 · 5 镜」必须是**同一条在变**，不是刷屏三条。

这决定了底层：**每件事有稳定 id，UI 订阅它变化**，而不是往消息数组里 push。不先定这条，17 种形态全都要返工。

> 行业依据（`docs/research/2026-08-24-agent-conversation-vocabulary-survey.md`）：「进度/中止：独立任务中心（虾条 8 态）或画布节点；**对话内原位进度无人做**」。别家把进度挪出对话，正是因为做不到原位更新。

**② 一件事一行，展开才有细节。**
17 种形态若都是卡片，对话流会变成卡片墙。所以默认全是单行，只有两类升级成卡片：**要你做决定的**、**产物本身**。17 种形态 → 视觉上只有 3 个层级。

**③ 诚实优先于好看。**
价格标出来、失败标人话原因 + 是否计费、上下文压缩了要说。

> 行业依据：「花钱确认：确认卡+点击才扣是主流；**没有一家卡上显示价格**」。TapNow 原文「手动确认只是让消耗发生在点击之后，不会免除消耗」= 半诚实反例。**反着做就是护城河。**

## 2. 统一状态词表（核心 · 先落这个）

### 2.1 现状：四套互不认识的说法

| 在哪 | 现在的词表 | 文件 |
|---|---|---|
| 消息 | `pending / streaming / done / error / cancelled` | [workbenchAiTypes.ts:14](../../src/workbench/ai/workbenchAiTypes.ts) |
| 步骤徽标 | `done / active / warn` | [AssistantTimeline.tsx:23](../../src/workbench/generationCanvas/components/AssistantTimeline.tsx) |
| 画布节点 | `idle / queued / running / success / error / recoverable` | [generationCanvasTypes.ts:8](../../src/workbench/generationCanvas/model/generationCanvasTypes.ts) |
| 镜头占位卡 | 第四套（用 `phase` 不用 `status`） | [ProductionShotPlaceholder.tsx:62](../../src/workbench/generationCanvas/nodes/ProductionShotPlaceholder.tsx) |
| **审批** | **没有词表** —— 靠 `pendingToolCalls[]` + `committedProposal` + `deviationReport` + `contentDeviations` 四个独立 state 拼 | `CanvasAssistantPanel.tsx` |

后果：`AssistantTimeline` 吃 15 个 props；每加一种 agent 行为要同时改四处。

### 2.2 目标：一套 8 态 + 2 标志

**8 个态**（互斥，任一时刻只处于一个）：

| 态 | 界面说法 | 什么时候 | 取代 |
|---|---|---|---|
| `drafting` | （无字，扫光中） | agent 还在流式吐这条 | 消息 `streaming` |
| `proposed` | 等你确认 | 提出来了，等用户点头 | `pendingToolCalls`（此前无名） |
| `declined` | 你拒绝了 | 用户拒了 | 此前无 |
| `queued` | 排队中 · 前面还有 N 个 | 已批准，等资源/等前置 | 节点 `queued` |
| `running` | 进行中 | 真在跑 | 节点 `running`、徽标 `active` |
| `done` | 完成 | 成了 | 节点 `success`、消息 `done` |
| `failed` | 失败 | 挂了 | 节点 `error`、消息 `error` |
| `stopped` | 已停止 | 用户中途叫停 | 消息 `cancelled` |

**2 个标志**（挂在态上，不是独立态）：

| 标志 | 挂在 | 取代 | 为什么不做成独立态 |
|---|---|---|---|
| `retryable` | `failed` | 节点独立态 `recoverable` | 它本来就是「failed + 能重试」。做成独立态 = 每个渲染分支都要多处理一个 case |
| `deviated` | `done` | 徽标 `warn` | 事实是「做完了 **且** 和批准的不一样」，不是 done 的替代。现在 warn 与 done 互斥是错的 |

### 2.3 颜色只有 4 组（不是 8 种）

| 组 | 含哪些 | token |
|---|---|---|
| 中性 · 在走 | `drafting` `queued` `running` | `--nomi-ink-40` |
| **要你动手** | `proposed` · 反问 · 付费 | `--nomi-accent` |
| 成了 | `done` · 写入回执 | `--workbench-success-ink` |
| 出事了 | `failed` `stopped` | `--workbench-danger` |
| 有偏差 | `done + deviated` | `--nomi-warning` |

## 3. 三个视觉层级

| 层级 | 什么进来 | 形态 |
|---|---|---|
| **一行** | 过程性的、不需要你做任何事 | 思考条 / 阶段线 / 工具条 / 排队 / 进度 / 写入回执 / 压缩线 / 上下文用量 |
| **可展开的一行** | 过程性但你可能想看细节 | 思考条（展开看推理）/ 计划行（展开改单镜参数） |
| **卡片** | ① 要你做决定 ② 产物本身 | 计划卡 / 付费卡 / 反问卡 / 失败卡 / 有出入卡 / 产物卡 / 多候选组 |

**纪律**：新增形态先问「它要不要你做决定、是不是产物」。都不是 → 只能是一行。

### 4.1 `queue` 现在是真 bug，不是新功能

输入框在 agent 忙时**没有禁用**，但 [CanvasAssistantPanel.tsx:220](../../src/workbench/generationCanvas/components/CanvasAssistantPanel.tsx) 是 `if ((!text && !readyAttachments.length) || busy) return` —— 用户打字按回车，**消息被静默丢弃，屏幕上什么都不发生**。视频生成动辄几分钟，这期间用户必然想说下一句。

同理 §4 的 #1：`agentUsageStore` 只有 `workbenchAgentRunner.ts:4` 在写，**零消费方**。

这两条建议提前到第一批 —— 它们不是锦上添花，是用户会当成「这软件坏了」的洞。

## 5. 等待指示器：工序图示

**不用品牌 N**（2026-08-27 用户否决）。理由是语义撞车：每条 assistant 消息头上已有 `NomiLogoMark`（[AssistantMessageView.tsx:20](../../src/workbench/ai/AssistantMessageView.tsx)），一屏能出七八个 N；且 **N = 身份**（这是 Nomi 在说话），等待 = **状态**（它在干什么），同一符号扛两义则两义都糊。

**改用「工序图示」**：图标随当前工序变，图标本身即进度。

| 工序 | 图示 | 动作 |
|---|---|---|
| 读本 | 一页纸 + 3 行 | 三行依次亮（1.9s） |
| 拆镜 | 3 个横格 | 依次落位（2.1s） |
| 出图 | 取景框四角 + 中心点 | 缩放呼吸 = 对焦（2.4s） |
| 出视频 | 场记板 | 上板打一下（1.9s） |
| 上轨 | 3 条轨道 | 短块往左走带（2.0s） |

### 5.1 §6 需要开一族新东西

主文档 §6 写死「唯一图标库 `@tabler/icons-react`，其它不许新增」。工序图示不在 tabler 里。

**不是破例，是划一族**：`NomiLoadingMark` 本身就是自画的品牌资产。同理设立 —— **「工序指示器」= 受管动效资产**：

- 只能由 `src/design/` 提供，业务代码不许自己画
- 每个必须在本文 §5 表格登记（工序名 / 动作 / 时长）
- 与通用图标分开：通用图标仍然只能用 tabler
- **长期成本**：每加一道工序要多画一个。加工序前先问「能不能并进已有的一道」

## 6. 文案纪律（片场话）

Nomi 是拍片工具，等待文案用**片场黑话**而非「正在思考中」。四条纪律：

1. **短等待（<3 秒）不轮播** —— 只说真话「正在读第三章」。3 秒的话还没看清就没了，轮播只会闪。
2. **按当前阶段取词，不乱串** —— 「正在架机位」出现在读剧本时就是胡说。句子按 §5 的 5 道工序分组。
3. **花钱 / 失败 / 扣费一律不俏皮** —— 这三个时刻用户在紧张，玩笑显得不靠谱。
4. **必配计时器**「已等 0:12」 —— 俏皮话是陪伴，计时器才是信息。

**文案要为布局让步**（§8 派生）：三等分按钮排里「换个模型重试」会挤，就写「换模型重试」。实现时长文案撑破行 = 设计错误，不是内容问题。

### 6.1 词库（zh-CN）

| 工序 | 句子 |
|---|---|
| 读本 | 正在通读第三章 / 正在跟场记对本 / 正在圈重点 / 正在数这场有几个人 |
| 拆镜 | 正在画分镜 / 正在排镜头顺序 / 正在想第一个镜头从哪切 / 正在给每镜配时长 |
| 出图 | 正在架机位 / 正在调焦 / 正在给灯师递话 / 正在等演员就位 |
| 出视频 | 正在打板 / 正在走位彩排 / A 机开始 / 正在盯回放 / 正在等这条过 |
| 上轨 | 正在压时间线 / 正在对字幕 / 正在垫音乐 / 正在剪掉废镜 |

**英文是已知缺口**（R15 要求走 i18n）：这批不能直译（「正在给灯师递话」直译即废）。英文需**二次创作**一批地道的（"Setting the key light" / "Waiting on the gaffer"…）。在那之前 `en` 回落到朴素版（"Generating…"），**不假装做完了**。

## 7. 动效规范

现状：主文档 §2.7 **只有一条 token**（`--nomi-transition-fast` 140ms）—— 「等待期长什么样」这一层从未定义过。这正是 agent 界面显得死板的根因。

### 7.1 主张

> **每个等待都要有脉搏，每个变化都要有交代。**

| 不做 | 做 |
|---|---|
| 渐变流光、粒子、发光边框、彩虹色（看三次就烦，且与纸感设计打架） | 扫光=还活着在跑 · 呼吸=在想 · 数字滚动=值刚变 · 滑入=这是新的 · 描边勾=成了 · 模糊转清晰=图正在出来 |

**分野纪律**：**等待类动效要慢、要低对比**（1.8–2.4s 循环，用户要盯几小时）；**状态跃迁动效才能快、才能明显**（一次性，值得看一眼）。

### 7.2 token（1 条 → 6 条）

| token | 时长 | 用途 |
|---|---|---|
| `--nomi-motion-tap` | 140ms | 交互反馈（**= 现有 `--nomi-transition-fast`，改名收口，不新增行为**） |
| `--nomi-motion-enter` | 260ms | 进场 / 退场 |
| `--nomi-motion-settle` | 420ms | 一次性跃迁：描边勾、数字落定 |
| `--nomi-motion-breathe` | 1.8s | 呼吸循环（在想） |
| `--nomi-motion-sweep` | 2.2s | 扫光循环（在跑） |
| `--nomi-motion-develop` | 900ms | 模糊转清晰（图在出） |

缓动统一 `cubic-bezier(.2,.7,.3,1)`（沿用现有）；循环类用 `linear` 或 `ease-in-out`。

### 7.3 三条硬纪律

1. **`prefers-reduced-motion` 一次性全关** —— 全部退化成静态。可访问性硬要求，不是选项。现有 `NomiLoadingMark` 已用 `motion-reduce:animate-none`，新组件照办。
2. **同屏最多 1 处扫光** —— 三个任务并行 = 三条进度条同时扫 + 三处呼吸 = 真吵。只有**当前活跃**那条动，其余降级成静态百分比。
3. **暗色模式必须单独验** —— 扫光在白底是「一道亮的扫过」，暗底要反过来。本轮样张只验了亮色。

## 8. 控件规格（尺寸 · 等宽 · 层级）

> 2026-08-27 用户两次点名：「有些按钮很大有些很小」「同行的按钮不能一个大一个小、一个长一个短」。根因是样张里出现了**设计系统里不存在的尺寸**（自造 `xs`=24px / padding 9px），以及**文字链与按钮同排**。

### 8.1 尺寸真相源（全部出自主文档，本节不发明）

| 元素 | 规格 | 出处 |
|---|---|---|
| 动作按钮 | **h-7 = 28px** · `px-3` = 12px · 12px 字 · **圆角 7px** | `WORKBENCH_BUTTON_SIZE.sm`（原注释：「时间线卡片内的紧凑动作」）+ `--workbench-control-radius: 7px` |
| 图标钮 | 28×28 · 圆角 7px · 图标 **16 / stroke-2** | `WorkbenchIconButton` `[&>svg]:size-4 [&>svg]:stroke-2` |
| 选择器 / 参数 pill | h-7 · `pl-2.5 pr-2` · 12px 字 · **药丸** | `NomiSelect` / `InlineParameterBar` 摘要 pill |
| 选项 chip | h-7 · `px-3` · 12px · 药丸 | 与选择器同族 |
| 文字链 | 无高度 · 12px · `--nomi-ink-60` | —— |
| 状态徽标 | 无高度 · 11px · 药丸 · `px-1.5 py-[1px]` · **不可点** | 主文档 §5.5 |
| 卡头语义图标 | **18** | 主文档 §6「弹窗/卡片头部语义图标（付费确认等）18」 |
| 行内小图标 | **13 / stroke-1.8** | 主文档 §6「节点角标内的小图标」 |

**一句话规则：所有可点的东西统一 28px 高。** 不是控件的（文字链、状态徽标）才没有高度。
**形状规则：选择器 / chip = 药丸；按钮 = 7px 方角。** 两者不能互串。

### 8.2 同排按钮四条

1. **同一排的动作按钮等宽均分**（`flex:1`），主次**只用颜色**分：深底(`--nomi-ink`)=主，描边=次。**层级不靠尺寸。**
2. **一排最多 3 个**；再多 → 主按钮 + 「更多」收起。
3. **文字链不与按钮同排** —— 要么单独成行，要么升级成按钮。（此前把次要动作降成文字链，恰恰制造了「一大两小」。）
4. **选项 chip 例外**：按内容定宽（它是**内容**不是动作），但同组高/圆角/字号必须一致。

**单动作最小宽 72px** —— 否则「撤销」会缩成小方块，跟别处按钮看着不是一族。

### 8.3 产物卡的动作归位

改/重跑**移到缩略图上悬停出现**，卡底只留「去画布」。不只是为了对齐：调研里星流是「单击产物直接下指令」、小云雀是「逐镜悬停重做」——**改产物就该在产物身上改**，不该在卡底排队。

### 8.4 建议加门岗（P2「能 grep 的做成棘轮」）

尺寸一致靠自觉必然再漂（本轮就是我手滑造了 `xs`）。已有 `check:tokens` 拦 hex 与任意 px 字号，但**控件高度没人拦**，这次的毛病正落在那个缝里。

```
check:controls → agent 交互组件内禁止出现 h-6 / h-9 / h-[24px] 等
                 非 h-7 / h-8 的控件高度；baseline 只减不增
```

R17 纪律：**加规则必须先验它会红。**

## 9. 参数条复用（批级 + 单镜两层）

**铁律：不在对话卡里另造参数 UI。** 计划卡/付费卡里的参数条 = **同一个 `InlineParameterBar`**（[InlineParameterBar.tsx](../../src/workbench/generationCanvas/nodes/InlineParameterBar.tsx)）。

它的控件**全由模型档案声明**（`DynamicModelControl` + `useDedupedModelSelect`）—— 换 seedream 出图，控件自动变图片那套；接新模型，卡里自动就有。这就是 P4「档案声明槽，通用系统负责填」。手写一排 chip = 每接一个新模型改两处。

### 9.1 为什么必须分两层

一条完整参数条 ≈ 350px（模型 ≤150 + 变体 + 摘要 pill 110 + 间距），5 行各一条塞不下。更重要的是**真实用法本就分层**：整批统一，个别例外。

| 层 | 位置 | 内容 |
|---|---|---|
| 批级 | 卡顶「这批用」 | 完整 `InlineParameterBar` = 这批的默认 |
| 单镜 | 每行右侧 | 默认显示「同上」；改过显示「已改 10s」+ 可「还原」；点行展开该行自己的参数条 |

**摘要 pill 在这里要 150px，不是节点上的 110px。** 样张真机截图看出来的：110/120px 时「16:9 · 5s · 720p」被截成「16:9 · 5s · 72…」，看着像坏了。节点上 110px 可接受（节点窄、且有 `title` 兜底），对话卡里有横向余量，别沿用。

这刚好咬合 master plan §4 的 v1 刚性「**一批内单 provider，一张卡一次授权一本账**」——批级参数条就是那份合同的可视化。

### 9.2 两个待解（本轮发现，未定）

1. **浮层在滚动的对话流里会脱节。** 源码注释：「静止浮层（非 Popover）：打开定位一次**绝不跟随**——composer 已在打开期间冻结（两框皆不动）」。在节点上成立（画布冻住），**对话流会滚**，卡片走了面板留原地。必须改成跟随，或在对话流内换成就地展开（不用 portal 浮层）。
2. **窄栏降级规则未定。** 样张按 430px 画；master plan §4.1 说右栏可拉宽/收窄，收窄到 320px 时批级参数条变成什么？倾向「模型下拉留着，摘要 pill 变纯图标钮」，但**尚未拍板**。
