## 1. 最终版三条结构决定（先定骨架，21 形态挂其上）

过渡版已经把地基做对了（8 态词表逐字落契约、状态色 4 组、role=log+回到最新、intentRole、引用后已变化）。最终版**不推翻地基**，只在三处结构上升级——这三处正是「过渡载具 → 最终形态」的分野：

### 决定 A：右栏从「单区会话流」升级成「双区 Agent 工作区」（③合流落地）

**过渡版**：右栏只有一条会话流（header → 上下文架 → 会话 transcript → 队列 → composer），拆解结果面板与它**互斥抢槽**。
**最终版**：右栏 = **Agent 工作区**，纵向双区：

```
┌─ Agent 工作区（右槽 · assistantWidth 340px）────────┐
│ ▛ header：品牌 · 线程 · 上下文用量 · 常驻技能 · 费用   │  ← 常驻顶条（形态 1/21）
│ ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔ │
│ ▛ 结果卡区（固定 · 不随聊天滚走）─────────────┐    │  ← 新增：③合流的「固定结果卡区」
│ │ [拆解结果 · 5 镜 ▾]  [其它可操作工件…]      │    │     collapse≠unmount，勾选/滚动/Run 状态保持
│ ▙▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁┘    │
│ ▛ 会话流（role=log · 底部锚定 · 回到最新）────┐    │  ← 主体：指挥/追问/进度/回执
│ │  用户气泡 / 思考条 / 工具条 / 计划卡 …       │    │
│ │                              [↓ 回到最新]   │    │
│ ▙▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁┘    │
│ ▛ 指令队列（忙时 · 输入框上方）─────────────┐    │  ← 形态 18，折叠显数量
│ ▙▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁┘    │
│ ▛ composer：上下文架 · 输入 · 底栏配置行 ────┐    │  ← 收簇后 ≤5 簇
│ ▙▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁┘    │
└──────────────────────────────────────────┘
```

**为什么这样改**：用户 2026-09-01 拍板③合流（`right-slot-agent-workspace-opinion.md`）——「新功能 = 新卡片，不再新立面板」。过渡版的「互斥抢槽」是**权宜**（epic 未落地时的让位策略，`video-deconstruction-v1.md` R-C-1 明标「过渡行为，落地后自然消失」）。最终版把互斥消掉：拆解卡进结果卡区、会话流在下方，**同壳并存**。这是 C9 的结构答案（见 §5）。

**结果卡区 vs 会话流的分工**（`right-slot-opinion.md` 七维论证 2/3）：需要**审阅/操作**的高密度工件（拆解分镜表、未来可操作产出）停结果卡区、**不随聊天滚走**（「对照修改」是最高频后续动作）；过程性的（追问/进度/回执/思考）在会话流、可滚走。判据 = §3 视觉层级的延伸：**「产物本身且需要持续操作」→ 结果卡区；「过程性/一次性」→ 会话流**。

### 决定 B：composer 底栏 7 控件收簇成 ≤5（过 §1.5）

**过渡版**：底栏 7 个常驻控件 `📎 @ 🔧 ✏️ ⚙️ 🔒 🤖 ↑`（附件/引用/技能/提示词/工作方式/审批/模型 + 发送），已顶满 §1.5 的 L1 ≤5 功能簇预算、零 headroom。
**最终版**：按 §1.5.3「先分组→再去重→再归位→最后才收纳」收成 **5 簇**（详见 §4，形态 19/composer）。核心手法是**归位**（不是收纳）：上下文架/技能标记本就是 §13.2 说的「L1 输入反馈，不另占工具栏入口」——把 `@`(引用) 和技能触发从底栏搬到**上下文架自己那一行**，底栏只留「输入配置」这一类心智。

### 决定 C：工作方式轴掰回 §14 的 3 档，补回「编辑选中」（C1）

**过渡版**：工作方式私造 4 档 `ask/guided/balanced/auto`（自主强度），且**丢了 `编辑选中`**，并把审批语义折进工作方式文案——这是唯一的**契约级方向偏离**（`RESIDENT-SHELL-DECISION.md` C 段）。
**最终版**：工作方式 = §14.1 的 3 档 `Ask / 编辑选中 / Agent`（agent 能碰什么），批准策略 = §14.2 的 3 档（问多少），**两根正交轴不串**。这是 C1 的设计答案（见 §5 + 决策表 D1）。

## 3. 三视觉层级 + 结果卡区（承 #194 §3 · 扩一层）

| 层级 | 什么进来 | 形态 | 住哪 |
|---|---|---|---|
| **一行** | 过程性、不需你做事 | 思考条/阶段线/工具条/排队/进度/写入回执/压缩线/上下文用量 | 会话流 |
| **可展开的一行** | 过程性但你可能想看细节 | 思考条(展开看推理)/计划行(展开改单镜) | 会话流 |
| **卡片** | ① 要你做决定 ② 产物本身 | 计划卡/付费卡/反问卡/失败卡/有出入卡/产物卡/多候选组 | 会话流（一次性决定）**或** 结果卡区（需持续操作） |
| **结果卡区**（新）| 产物本身 **且** 需持续审阅/操作、不该被滚走 | 拆解分镜表 + 未来可操作产出 | 结果卡区（固定） |

**判据**：付费卡/反问卡/失败卡/有出入卡都是「决定一次就完」→ 留会话流随流；拆解分镜表是「对着它逐镜改，反复用几十分钟」→ 进结果卡区固定。多候选组是边界情形：暂存期在会话流（挑版），`accept` 后落画布——不进结果卡区。

## 7. composer 收簇账（7→5 · 过 §1.5）

**过渡版底栏 7 控件**（顶满 L1 ≤5 预算、零 headroom）：📎附件 · @引用 · 🔧技能 · ✏️提示词 · ⚙️工作方式 · 🔒审批 · 🤖模型 · ↑发送。

**收簇手法（§1.5.3 优先级：先分组→再去重→再归位→最后才收纳）**：

| 原控件 | 手法 | 去哪 | 代价 |
|---|---|---|---|
| @引用 | **归位** | 上下文架那一行（§13.2「L1 输入反馈不另占入口」）——`@` 触发从底栏移到上下文架的「+ 加引用」 | 0 |
| 🔧技能 | **归位** | 同上，技能 chip 与引用 chip 同住上下文架，`+ 技能` 触发在那一行 | 0 |
| ⚙️工作方式 + 🔒审批 | **分组** | 合成一个「执行方式」簇：一个触发点开二级面板，上半工作方式(3档)、下半批准策略(3档)——**两轴仍正交、只是同一个入口的两段**（不是并成一个选择器，那会违反正交，synthesis 节 6.13） | +1 点击（但从 2 簇降到 1 簇）|

**收簇后底栏 5 簇**：📎附件 · ⚡执行方式(工作方式+审批二段) · 🤖Agent模型 · ✏️提示词选择器 · ↑发送。

**为什么这样收**：@/技能是「输入内容的补充」（属上下文架心智），工作方式/审批是「这一轮怎么执行」（属执行心智），模型/提示词是「用什么理解」——归位后底栏只剩「配置这一轮怎么发」一类心智。**不往 ▾ 硬塞**（§1.5.4 反例：为凑数收中频控件=净负收益）；@/技能是**归位**（0 代价）不是收纳。上下文架/技能标记/上下文用量本就不该占底栏（#194 §13.2），过渡版把它们的触发混进底栏才顶满预算。

## 8. 右槽互斥的完整交互（Agent↔拆解 · 动效 + 角标）

> 终局是③合流双区并存（§1 决定 A + 屏 D）；**过渡期**（交互 epic 双区外壳落地前）走互斥（`video-deconstruction-v1.md` R-C-1~2 标「过渡行为，落地后自然消失」）。本节规定过渡期互斥的动效/角标规格 + 终局并存的切换。

### 8.1 过渡期互斥（屏 C）
- **右槽同一时刻一个住户**：`{ Agent 栏 | 拆解面板 }` 二选一。
- **拆解开 → Agent 收成顶栏角标**：落 `NomiAppBar` 右簇，紧挨「配置」组左侧，复刻现役 ghost 钮（`h-[30px]` + `IconX size=15 stroke=1.8`）。**有新动静**（新回复/工具跑完）冒 accent 小圆点或数字（语法复刻 `TaskCenterButton.tsx:143-147`：`min-w-4 rounded-pill bg-nomi-paper text-micro tabular-nums text-nomi-accent`）。点角标=还原右栏。落顶栏因为它是唯一跨创作/生成/预览常驻的 chrome。
- **Agent 开 → 拆解收成源节点浮条 + 节点角标**：源视频节点头挂「已拆解·N镜」角标，节点内挂「拆解结果·N镜」浮条。点浮条=展开右槽那张表。落节点因为拆解结果本就属那条源视频（一功能一个家）。
- **动效**：进驻用 `--nomi-motion-enter` 260ms 滑入；让位者淡出成角标/浮条（260ms）。**收起=collapse≠unmount**：勾选进度/滚动位置/进行中 Run/对话上下文，收起后点回原样还在。两个收起标志在同一 store 事务里互翻（避免两个都展开的中间态）。
- **切换动效纪律**：滑入/淡出走 enter(260ms)；角标新动静脉冲走 settle(420ms) 单次；**不同屏两处扫光**（切换期只一处活跃）。

### 8.2 终局并存（屏 D · 互斥消失后）
- epic 双区外壳落地 → 互斥标志作废（C9 删旧）。拆解卡进**结果卡区**（固定、不随会话滚）、Agent 会话流在下方，**同壳并存**。
- 拆解卡收起=折叠不卸载（结果卡区内折叠成 `拆解结果·5镜 ▾`）；展开占满槽宽做全幅表格。
