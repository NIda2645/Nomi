**4 次「被拒」全部是 harness 自己的缺陷，不是产品拒绝**：报文都是
`Video mode first does not match transport task image_to_video`——正是验收方自己记下的
那条已知限制（first/omni 模式的 transport 映射撞车）。协调方要求修它，本轮**没修**（见下）。

**读法**：这组数字量到的是「分级披露让外部面从『连计划都提不出来』变成『大多数情况能提出来』」，
以及**模型真的会自己去查第二档**（6/8 做了两跳）——这正是分级披露成立与否的关键行为。
它**没有**量到「参数写错会不会被拒、拒了能不能自纠」：准入层这一轮一次都没被真正触发。

## 没做的（如实记）
- **harness 的 first/omni transport 映射没修**，所以 4 个 run 的功力被它吃掉了。
- **没有在 `origin/main` 上复跑**：要另起一个带 node_modules 的 main checkout，本轮预算不够。
  故表格左列用的是验收方在 main 上测得的 0/8，两列**不是同一次会话、同一天**跑的。
- 样本量小（8 题 ×1 轮），只能当方向性信号。
