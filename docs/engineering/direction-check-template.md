# 方向检查：类根因复盘模板（RW）

> 什么时候写：`node scripts/fix-churn.mjs <路径>` 命中，或下面「触发」任一条出现。写完一页，结构性结论交用户拍板。
> 提交 fix 时在提交信息里加一行 `Direction-Check: docs/…/你的复盘.md`（git commit-msg 会校验文件存在、在 `docs/` 下、不是空壳）。
> 同一份复盘可以被同一概念的多个 fix 提交引用，不必每个提交写一份。

## 触发（任一即停止派修补，先写这份）

1. 同一文件或同一概念目录，14 天内第 3 个 fix 提交（`fix-churn.mjs` 能算）。
2. 出现 revert 一个 fix 的提交（`fix-churn.mjs` 能算）。
3. 修复因评测分数下降被回滚（人工判）。
4. 同一条线派第 3 轮及以上修补，交接单 / 任务书里写的「第 N 轮」同样算（人工判）。
5. 要加第三个特例分支（人工判）。

## 动作

停止派修补 → 先写特征测试钉住现状 → 写下面七节（一页，别写成论文）→ 结构性结论交用户拍板。
