## 🟡 架构教训

### ShotPlan：FRoPE 规划 token 把「转场时刻」提升为一等公民

- **链接 / 日期**：[arXiv 2607.17675](https://arxiv.org/abs/2607.17675)，v1 **2026-07-20**；Su Guo、Guangce Liu 等，China Telecom TeleAI + 哈尔滨工业大学。**代码公开**：[github.com/Pensioner-11/ShotPlan](https://github.com/Pensioner-11/ShotPlan)，**74 star**，含 inference/ + train/ 目录，预训练权重在 Hugging Face（Pensioner/ShotPlan-Wan2.2-T2V-A14B-HighNoise）。
- **一句话洞察**：在视频生成 token 序列里插入**可学习的规划 token**，配 **Fractional Temporal Rotary Position Embedding（FRoPE）**，让每个规划 token 携带「这一刀转场发生在第 N 帧」的精确时刻编码——硬切 / 软转 / 相机运动的时序约束因此从「文本描述模糊告知」变成「帧级索引精确控制」。在 13K 精选多镜头片段上训练，支持任意镜数组合。
- **影响 Nomi 哪个决策**：Nomi 的 storyboard schema 目前每个镜头描述结束即等于该镜的边界，没有显式的「转场帧」字段。ShotPlan 的教训是：**把转场时刻作为一等公民写进 storyboard 输出结构**，让后续拼接器知道「这两镜之间是硬切还是 0.5s 软溶入」。改法极轻：在拆镜头规划师的输出 JSON schema 里加 `transition_type`（`"hard_cut" | "dissolve" | "fade"`）和可选的 `transition_duration_s`（秒），让已有的拼接步骤读这个字段而非统一硬切。与 08-18 PACR-Video 的 `role` 字段教训**合并成一次 schema 改动**：同时加 `role`（叙事功能）+ `transition_type`（转场类型），改一次够用。
- **诚实边界**：ShotPlan 的 FRoPE 需要在 Wan2.1-14B 基础上重新训练，Nomi 走供应商 API 无法直接用其权重。落地点仅是**数据结构契约**（schema 字段），不是运行时能力。ShotPlan 的转场精度需要模型端支持，Nomi 暂时靠拼接脚本实现（精度差但可迭代）。

### CausalCine：CAMR——按注意力相关性而非时序就近取历史上下文

- **链接 / 日期**：[arXiv 2605.12496](https://arxiv.org/abs/2605.12496)，v1 **2026-05-12**；Yihao Meng、Zichen Liu、Hao Ouyang 等；项目页 [yihao-meng.github.io/CausalCine](https://yihao-meng.github.io/CausalCine/)。**暂无公开代码仓**（本轮实查项目页未见 GitHub 链接）。
- **一句话洞察**：**Content-Aware Memory Routing（CAMR）** 的核心论断：多镜生成时「取最近几个 KV entry」是错误的默认策略——正确做法是按**注意力相关性分数**动态检索历史 KV，相关性高的历史镜头（不管在第几镜）优于时序上紧邻但语义无关的镜头。配套把因果基础模型蒸馏成 few-step 生成器，实现实时交互多镜生成。
- **影响 Nomi 哪个决策**：Nomi 在 `generationReferenceResolver.ts` 里当前是「按镜头编号顺序取最近 N 个参考」。CAMR 的教训：**context 排序应按「这个历史帧对当前镜头的相关度」**，而不按「谁离我近谁上」。改法：在参考帧候选列表里加一个 VLM 相关性打分（问「这帧里的实体/场景和当前镜头描述的相关度」，0-10），取 Top-K 而非顺序前 K。这和 08-17 EM-Vid 的「实体相关性排序」是同一个教训的两个视角——**合并进 `generationReferenceResolver.ts` 的同一次改动**，不开独立工单。
- **诚实边界**：CAMR 的完整实现在扩散因果模型的 KV-cache 层，Nomi 碰不了模型内部。可采纳的只是**排序策略**：用 VLM 代替注意力分数做代理相关性打分。无公开代码，细节需自行推导。CausalCine 整体需要训练，不能直接接入 Nomi。
