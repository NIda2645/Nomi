## 一句话总结

本轮 **🟢 2 / 🟡 2 / 🔵 1**。主线从「怎么让单镜更准」转向 **「谁来管全片的全局创意决策」**——Co-Director 用一手数字证明：在 Nomi 已有的逐镜 VLM 校验之上，缺的那层不是更严的单镜打分，而是**一个全片级的创意方向选择器**（同样 4 次迭代预算，有向选择 81.4 vs 随机搜索 75.7）。

**本轮最该动的两件事：**

1. **给 `StoryboardPlan` 加一层「全片创意方向」参数，并让它自顶向下注入每镜 prompt**（Co-Director 🟢）。现状核实：`src/workbench/generationCanvas/agent/storyboardPlan.ts:72` 的 `StoryboardPlan` 只有 `title / anchors / shots`——**没有任何全片级创意方向字段**（grep `style|tone|genre|direction|creative|aesthetic` 只命中 `PlanAnchorKind` 里的 `'style'` 锚，那是「跨镜要一致的视觉风格锚」，不是「这片子用哪种叙事策略」）。Co-Director 的 θ 三轴（创意策略 / 叙事模式 / 美学原型）恰好补这个空。**先做最小版：θ 作为显式计划字段 + Orchestrator 把 θ 翻译成各镜指令**，不要一上来就做 bandit 采样（见落地档细节）。
2. **给参考锚点加「验收才入库」门**（EM-Vid 🟢 复证 08-12 GroundShot）。现状核实：`generationReferenceResolver.ts` 与 `referenceAncestors.ts` 里 grep `shotVerify|verifyScore|passThreshold` **零命中**——即「未通过验收的帧不进锚点」这条 08-12 就提过的不变量**至今没落**。而 Nomi 其实已经有现成裁判（`shotVerify.ts` 的 identity/composition/continuity 三轴 + `SHOT_VERIFY_PASS_THRESHOLD`），本轮 EM-Vid 从第二个独立方向再次指向同一结论：**接线活，不是新研究**。

## 🟢 可落地

### Co-Director：训练无关的「全局创意方向选择 + 局部自我精修」双层导演框架

- **链接 / 日期**：[arXiv 2604.24842](https://arxiv.org/abs/2604.24842)，v1 **2026-04-27**；项目页 [co-director-agent.github.io](https://co-director-agent.github.io/)（无代码仓，但机制与参数在正文/附录写全）。作者含 Yale Song、Tomas Pfister 等（Google 系阵容，17 人）。
- **一句话洞察**：把「视频叙事」形式化成**全局优化问题**而非流水线——上层用 multi-armed bandit（UCB1 + LLM 暖启动）在 36 种创意配置里选方向，下层用多模态自我精修循环修身份漂移；**全流程纯推理、零微调**（backbone 是 Gemini 3 Pro + Veo 3.1 + Nano Banana Pro + Gemini 2.5 Pro TTS + Lyria 2 的现成 API 串联）。
- **机制拆解**（这是能照搬的部分）：
  - **θ = 三条正交分类轴**：创意策略（Informational / Transformational / Comparative）× 叙事模式（Analytical / Vignette / Narrative Drama）× 美学原型（Clarity-Energy / Cinematic-Premium / Minimalist-Focus / Kinetic-Grit）= 3×3×4 = 36 臂。
  - **factored reward**：奖励拆成 `(r_cs, r_nm, r_aa)` 三个 [0,100] 分量，所以**一次执行能同时更新三个轴**——这才是它只用 T=4 次迭代就不用穷举 36 臂的原因。
  - **Orchestrator 自顶向下注入**：选定的 θ 被翻译成各 sub-agent 的 system prompt 指令（论文 Table 6 的例子：Informational + Vignette + Clarity/Energy → 「强调功能性效用」「氛围化小品」「高时序运动剪辑、快切」），保证所有 agent 朝同一创意意图对齐，而不是各自解读参数。
  - **局部精修**：storyline 用 LLM 评（钩子/连贯/产品融入/吸引力）、keyframe 用多模态 LLM 评（视觉一致/叙事流/吸引力），低于阈值 τ 就带着可执行反馈**选择性重生成**被标记的部分。
- **一手数字（GenAd-Bench，400 场景）**：Co-Director (T=4) 平均 **81.4** > Random Search (T=4) **75.7** > Base Pipeline (T=1) **68.5** > MovieAgent **65.3** > Veo 3.1 单发 **63.6** > AniMaker **62.2**。人评 MOS 3.96 vs Veo 3.1 3.71 / AniMaker 3.07。
- **为什么这条是本轮头条（对 Nomi 的真实增量）**：Nomi 已经有它的**下层**了——`shotVerify.ts:13` 的 `ShotVerifyDimensionKey = 'identity' | 'composition' | 'continuity'`、阈值门 + `deviationsFromVerdict` → `contentDeviationsToReconcile` 的反馈重做链，结构上等价于 Co-Director 的局部精修循环。**Nomi 缺的是上层**：没有任何东西在决定「这一整片走哪种叙事策略/美学」，全靠用户 prompt 里碰巧写了什么。而 81.4 vs 75.7 这一栏说明：同样花 4 次预算，**有向的方向选择比随机重试多赚 5.7 分**——即「多试几次」不能替代「想清楚往哪试」。
- **落到哪个模块 / 怎么改**（分两步，第一步不花额度）：
  1. **加计划字段（先做这个）**：在 `src/workbench/generationCanvas/agent/storyboardPlan.ts` 的 `StoryboardPlan`（:72）+ 同文件 zod schema（:84 起）加一个 `direction?: { strategy, narrativeMode, aesthetic }` 三轴字段（**轴的取值要按 Nomi 用户的真实场景重定义，不照抄广告 taxonomy**——Co-Director 的 36 臂是为「虚构产品广告」设计的）；在 `storyboardPlan.ts:305` 起那段「文本锚描述拼进镜头 prompt」的既有路径上，把 `direction` 同样自顶向下拼进每镜 prompt（复用现成机制，不新开管线）。这一步就是 Co-Director 里真正扛事的「Orchestrator 注入」，**不需要 bandit**。
  2. **再考虑 bandit（第二步、可选）**：`storyboardLoopBudget.ts` 已有循环预算概念，是接 T=4 迭代的天然位置；奖励可复用 `shotVerify` 分数聚合。**但这一步会把额度×4**，且 Nomi 是本地优先工具、用户在场，「让用户从 2-3 个方向里挑」很可能比「自动跑 4 轮 bandit」更贴 D1（effect-first、别让用户等）。**建议先只做第 1 步 + 人挑方向，把 bandit 留作后续实验**。
- **诚实边界**：① 数字全部来自 GenAd-Bench = **虚构产品广告**场景，Nomi 用户虽多为现代商业/营销（与之较贴），但绝对值不可直接搬；② 无代码仓，只能按论文描述重建；③ backbone 是 Google 全家桶，Nomi 多供应商解耦（P4）下 θ→prompt 的翻译效果需自测；④ 「17.6% 相对提升」是对 Base Pipeline(T=1) 而言，**不是对随机搜索**——对随机搜索是 +7.5% 相对，报数别放大。

### EM-Vid：训练无关的实体级 latent 记忆 + 稀疏 token 条件化（复证「验收才入库」）

- **链接 / 日期**：[arXiv 2605.23610](https://arxiv.org/abs/2605.23610)，v1 **2026-05-22**；作者 Jente Vandersanden、Matheus Gadelha、Chun-Hao P. Huang、Hyeonho Jeong、Yulia Gryaditskaya——**Max Planck Institute for Informatics + Adobe Research**（lab 信号强）。无公开代码仓 / 项目页（已实搜确认）。
- **一句话洞察**：多镜一致性的记忆**不该存整帧**——存「实体索引的 latent patch 银行」（entity-indexed bank of latent patches），把「持久的实体信息」和「一次性的场景上下文」分开；检索时用 sparse token conditioning 只让自注意力看**与该实体相关的 token**（顺带省算力）；配 budgeted memory update 保持记忆紧凑演化 + noise-injection 控外观。**训练无关、兼容预训练模型。**
- **落到哪个模块 / 怎么改**：`src/workbench/generationCanvas/runner/generationReferenceResolver.ts`（引用决策，`resolveGenerationReferences` :111）+ `referenceAncestors.ts`（锚点收集，`collectUngeneratedReferenceAncestors` :18）。两条具体不变量：
  1. **验收门（本轮最该接的线）**：已 grep 核实这两个文件里 `shotVerify|verifyScore|passThreshold` **零命中**，即任何生成结果都能当后续镜头的参考，**不管它身份对不对**。Nomi 已有 `shotVerify.ts` 的 identity 轴打分 + `SHOT_VERIFY_PASS_THRESHOLD`，只需在参考候选筛选前接上：**identity 未过阈值的帧不得成为后续镜头锚点**。这条 08-12 由 GroundShot 提出、本轮 EM-Vid 从独立方向复证（两篇不同 lab、都 training-free），**属于「两个独立来源指向同一结论」的强信号，不该再拖一轮**。
  2. **按实体分槽 + 按实体相关性检索**：`referenceSlots.ts` 已有槽位概念，EM-Vid 的「实体索引」与 Nomi 的 `PlanAnchor.kind`（`character|scene|prop|style`，`storyboardPlan.ts:15`）天然对齐——检索该镜参考时按**该镜 `anchorIds` 涉及的实体**取，而不是无差别把所有锚点/最近帧塞进去。
- **诚实边界**：EM-Vid 的 latent patch bank 与 sparse token conditioning 是**在扩散模型注意力层内部**动手的，Nomi 走供应商 API、**拿不到 latent 层**——所以论文的算力收益和外观控制部分**照搬不了**，Nomi 能采用的只是它的**调度契约**（分实体存、验收才入、按实体检索）。这与 08-12 对 GroundShot 的判断一致：采契约、不采内部模型。无代码，无法复现其数字。

## 🟡 架构教训

### VideoWeaver：agent-as-judge 要审「执行轨迹」，不只审最终产物

- **链接 / 日期**：[arXiv 2606.08091](https://arxiv.org/abs/2606.08091)，v1 **2026-06-06**；作者 Jianhui Wei 等（同作者另有 [UniVBench, CVPR 2026](https://github.com/JianhuiWei7/UniVBench)，credibility 信号）。**代码 + 数据集已开源**：[github.com/JianhuiWei7/VideoWeaver](https://github.com/JianhuiWei7/VideoWeaver)，CC BY 4.0。**star 仅 ~7**（很新，火度低，按筛选维度 2「新论文看代码/repo 信号而非引用数」仍收）。
- **一句话洞察**：benchmark 有 16 类任务 / 285 case，但真正的教训在评法——**agent-as-judge 同时检查「执行轨迹」和「最终视频」**，把打分锚在证据上（metadata、中间产物文件），而不是只看成片。另一半是 skill library：agent 不走预设流水线，而是把 foundation skill 组合成自己的 workflow，再由 skill evolution 迭代精炼/合并这些组合技能。
- **影响 Nomi 哪个决策**：这条**不是 🔵 而是 🟡**，因为它评的是「通用 agent 框架能不能干长视频活」，与 Nomi 的固定管线不同构，benchmark 本身接不进来。但它对 Nomi 的 eval 体系有一条真教训：`evals/lib/` 现有 `judge.mjs` / `vbenchRubric.mjs` / `journeyRunner.mjs` 都是**看产物打分**（`vbenchRubric.mjs` 的维度全是单图/单视频轴：alignment / aesthetic / imaging / subject_consistency / motion_smoothness / temporal_stability / dynamic_degree）。VideoWeaver 的做法提示：Nomi 的 journey/eval 应当**同时把「过程证据」纳入判据**——重试了几次、哪镜触发了 reconcile、锚点是否被降级复用——这些 Nomi 已经在 `shotVerifyStore.ts` / `generationQueueStore.ts` 里产生了，只是没进评分。这也正好接上 **R16「真实任务端到端测试系统」**：R16 要的就是「带真实任务跑通闭环」，而闭环质量恰恰藏在轨迹里而非成片里。
- **诚实边界**：star 数极低、无第三方复现；论文结论（「显式组合技能优于裸 foundation skill、skill evolution 再提升」）是在它自己的 285 case 上得出的，不构成对 Nomi 管线的直接证据。**不建议引入其 skill-evolution 机制**——Nomi 是固定管线 + 用户在场，自主演化技能与 P1（无并行版）冲突。

### PhyPrompt：prompt 改写器一旦需要 RL 训练，就出了 Nomi 的能力边界

- **链接 / 日期**：[arXiv 2603.03505](https://arxiv.org/abs/2603.03505)，v1 **2026-03-03**；作者 Shang Wu、Chenwei Xu、Manling Li、Han Liu 等。无公开代码。
- **一句话洞察**：两阶段 RL（LLM 物理推理微调 + GRPO 渐进奖励课程）训出的 prompt 改写器，能把物理常识从 55.8% 提到 66.8%（VideoPhy2 joint success 40.8%，+8.6pp），且**zero-shot 跨 T2V 架构迁移**（Lavie / VideoCrafter2 / CogVideoX-5B，最高 +16.8%）。
- **影响 Nomi 哪个决策**：跨模型 zero-shot 迁移这一半**符合 P4 解耦**、很诱人；但产出这个改写器**必须 RL 训练**（GRPO + 奖励课程 + 视频物理奖励模型），Nomi 拿不到那个算力/数据闭环。教训是给 prompt 方向划一条线：**Nomi 的 prompt 优化只走「推理时」路线**（08-12 的 3R = RAG 检索修饰词 + 分布对齐改写，training-free），把 PhyPrompt 这类「训练时」方案明确排除在选型外，别在 `storyboardPlan.ts` 的 prompt 改写节点上反复纠结。附带一条可白嫖的：它的**物理合理性**作为 prompt 改写的评价维度是有价值的——Nomi 可以把「物理常识」加进 `vbenchRubric.mjs` 作为人工/VLM 打分轴，而不必训模型。
- **诚实边界**：无代码；基线 T2V（Lavie / VideoCrafter2 / CogVideoX-5B）均为较老开源模型，对 Nomi 接的商用 API（Veo/Kling 级）是否还有同等增益**未知**——这些模型自身的物理表现已远好于论文基线，增益很可能被压缩。

## 🔵 对标基准

### EntityBench：带「保真门」的三支柱多镜评测（正是 Nomi 缺的那道门的评测版）

- **链接 / 日期**：[arXiv 2605.15199](https://arxiv.org/abs/2605.15199)，v1 **2026-05-21**。140 集 / 2,491 镜，取自真实叙事媒体，带**逐镜实体时刻表**（characters / objects / locations 同时追踪），难度分 easy/medium/hard，最长 50 镜、13 个跨镜角色、8 个跨镜地点、22 个跨镜道具，**复现间隔最长跨 48 镜**。
- **一句话洞察**：三支柱把纠缠的分数拆开——**镜内质量 / prompt 遵循 / 跨镜一致**；关键设计是 **fidelity gate（保真门）：只有实体外观「准确」的镜头才被允许进入跨镜一致性打分**。否则模型可以靠「稳定地画错同一个人」骗到高一致性分。
- **怎么接进 Nomi eval**：① **概念上先接门**：这道 fidelity gate 与本轮 🟢 EM-Vid 的「验收才入库」是**同一条不变量的评测面镜像**——生产侧要求「没过验收的帧不当锚点」，评测侧要求「没过保真的镜不进一致性分」。Nomi 的 `evals/lib/vbenchRubric.mjs` 现在把 `subject_consistency` 和 `alignment` 平铺在同一组维度里、**无任何门控**，等于允许「稳定画错」拿高分——建议改成：`alignment`（≈保真）不过阈值的镜头，其 `subject_consistency` 不计入跨镜聚合。② **数据上取难度梯度**：借它的「复现间隔」概念给 Nomi 的多镜 fixture 分档（间隔 1-2 镜 / 5-10 镜 / >20 镜），量化 Nomi 身份保持随间隔的衰减曲线。
- **与既有 eval 的关系**：与 08-12 的 KathaTrace（🔵，STG 量语义断层）**互补不替换**——EntityBench 管「实体是不是同一个」，KathaTrace 管「叙事有没有断」，VideoArgus（08-09）管单镜质量。三者构成 Nomi eval 的三层。**注意 `vbenchRubric.mjs` 至今仍无跨镜/叙事维度**（已核实：现有维度全是单图/单视频轴），08-12 提的 `narrativeCoherence` 维度**仍未落**。
- **诚实边界**：素材取自真实叙事媒体（影视剧级），Nomi 用户场景为商业/营销短片，绝对分不可比；本轮未确认其数据集是否已公开可下载（论文页未见 HuggingFace 链接），**「取 50 条做 fixture」这一步待核实数据可得性**——若不可得，则只采用它的两个设计（保真门控 + 复现间隔分档），这两个不依赖它的数据。
