# Nomi 论文雷达 · 2026-08-31

本轮按固定 8 方向定向检索近 6 个月 arxiv（截止窗口 ≈2026-03-01），每条过「最新/热度/对痛点有用/成熟度」四关，强制三档分诊。所有论断来自本次实搜（WebSearch + WebFetch 深挖 8 篇），带 arxiv 链接与日期。没有把「有代码但没查到 repo」写成「已验证可用」。

## 今日结论

- **🟢 可落地：1**。[GroundShot](https://arxiv.org/abs/2606.20799)——training-free + model-agnostic 的多镜实体记忆 + 镜头调度，架构和 Nomi 的 reference-relay 高度同构，方法层可直接借（不需重训、不绑模型，符合 P4）。
- **🟡 架构教训：2**。[DirectorBench](https://arxiv.org/abs/2605.30090) 和 [KathaTrace](https://arxiv.org/abs/2607.01312) 同时给出同一条硬结论：**decompose-stitch 的瓶颈在「镜间」和「规划」，不在单帧画质，也不在 provider 数量**。DirectorBench 直接把 ViMax（= Nomi 的 script→storyboard→首帧→逐镜 t2v→后期合成 这条流水线的原型）评为最差，temporal coherence 只有 0.18、跨系统 transition 均分 0.256；KathaTrace 量化出「改规划师 -11.2 分 vs 改渲染 -4.1 分」。
- **🔵 对标基准：2**。[EntityBench](https://arxiv.org/abs/2605.15199)（140 集 / 2491 镜，专测跨镜实体一致）比上轮的 MSVBench 更贴 Nomi 命门；DirectorBench 作 checkpoint 级诊断卷（80 条 / 5 维 / 40 检查点，repo+HF 公开）。
- **本轮最该动的 1 件事**：把「一名角色跨 6 镜 + 一次镜间转场」做成一条**离线可跑的评测任务**（复用 EntityBench 的「首次清晰出场做锚、后续每次出场比锚」这条度量思路），接进 `evals/journeys/`，用它量 Nomi 现在的 reference-relay 到底掉在哪。这比再接一个 provider 有价值——学术界已经用同一张卷子证明「继续堆 stitch / 堆 provider」不解决 coherence。
- **第 2 件（方法层，非本周必做）**：读 GroundShot 的「按实体参考价值排镜头生成顺序 + 只把验证可靠的实体入记忆」，评估能否落到 `dependencyWaves.ts`（现在的生成波次）+ `referenceSlots.ts` / `relayFrameResolver.ts`（现在的参考中继）。

## 🟢 可落地

### GroundShot — 训练无关的多镜实体记忆 + 镜头调度
- **arxiv**：[2606.20799](https://arxiv.org/abs/2606.20799) · 2026-06-18（v3 2026-07-20）
- **为什么是头条**：明确自述 "training-free, model-agnostic agentic framework"，无需额外训练或改模型——**这正好是 Nomi 的接入姿势**（P4 解耦，接任意 provider）。核心洞察一句话：**「观众判断一致性，是拿角色每次后续出场跟它第一次清晰出场比」**，所以它 ① 在线从「已接受的镜头」里建实体级视觉记忆；② 按「一个镜头作为实体参考的预期价值」排生成顺序；③ 从生成视频里 ground 出实体、**验证可靠后才入库**；④ 每镜生成前先检索合适的实体参考。
- **落到哪**：方法层直接对应 Nomi 现有三块——生成波次 `src/workbench/generationCanvas/runner/dependencyWaves.ts`（对应「排镜头顺序」）、参考槽/祖先解析 `runner/referenceSlots.ts` + `runner/referenceAncestors.ts`、帧中继 `runner/relayFrameResolver.ts`（对应「检索实体参考」）。现状 Nomi 的中继是**结构依赖驱动**（上游节点→下游槽），GroundShot 多一层「按参考价值主动调度 + 入库前验证」的语义。**先不动生产**：先在评测任务里量 Nomi 当前中继的跨镜身份掉分，再决定要不要引入「实体价值调度」这层。
- **成熟度**：training-free ✓、model-agnostic ✓；**但本次未查到官方 repo/项目页**（arxiv 页与两次搜索都没给代码链接），标「代码待核实」——落地前需确认能否拿到实现或按论文复述自建。

## 🟡 架构教训

### DirectorBench — 有人拿 ViMax(≈Nomi 原型) 当卷子，判了最差
- **arxiv**：[2605.30090](https://arxiv.org/abs/2605.30090) · 2026-05-28 · **repo + HuggingFace 数据集公开**
- **洞察**：把 ViMax 一字不差描述成 "open-source decompose-stitch pipeline whose base LLM produces a script, then a storyboard, then a first-frame image per shot, then runs per-shot text-to-video, and finally composes background music and voiceover post-hoc"——**这就是 Nomi 的流水线原型**。四系统排名 Kling Canvas Agent > Dreamina Creation Agent > MovieAgent > **ViMax（最差）**；ViMax temporal coherence **0.18**，跨工作流 transition 均分 **0.256**，inter-unit 质量普遍远弱于单帧质量。
- **影响 Nomi 哪个决策**：**别再把「加 provider / 提单镜画质」当主路**。同一张卷子已证明纯 decompose-stitch 在 coherence 上有结构性天花板；Nomi 的差异化投入应压在**镜间**（转场 + 实体中继）和**规划质量**上，不是广度（呼应 D2「广度是敌人」）。可把它的 5 维 40 checkpoint 借作内部诊断骨架（见 🔵）。

### KathaTrace — 「语义轨迹坍缩」：改规划师的收益是改渲染的 2.7 倍
- **arxiv**：[2607.01312](https://arxiv.org/abs/2607.01312) · 2026-07-01 · [项目页](https://jamunasmurthy.github.io/kathatrace/)（代码释出待核实）
- **洞察**：诊断工具（非生成器）。定义失败模式 "semantic trajectory collapse"——**画面各自都连贯，但镜间的因果/情绪/后果链断了**。关键实验：渲染器固定、只改规划器，坍缩指标降 **11.2** 分；只改渲染器仅降 **4.1** 分。结论：**planning quality > rendering quality**。
- **影响 Nomi 哪个决策**：把资源和评测重心放在**拆镜头/故事板规划师**（`src/workbench/` 的 storyboard 相关：`workbenchStore.ts` / `storyboard.test.ts` / storyboard 编排）而非追单镜画质。也提示评测要**显式测「镜间因果/情绪是否存活」**，不能只测「每镜好不好看」。与 DirectorBench 同向互证。

## 🔵 对标基准

### EntityBench — 跨镜实体一致的专用卷（比上轮 MSVBench 更贴命门）
- **arxiv**：[2605.15199](https://arxiv.org/abs/2605.15199) · 2026-05-14（repo 链接待核实）
- **测什么**：140 集 / **2491 镜**，easy/medium/hard 三档，单集最多 50 镜、最多 13 个跨镜角色 / 8 个跨镜地点、复现间隔跨 48 镜。三层度量：intra-shot 画质（6 个 VBench 类指标）、intra-shot prompt 对齐（实体在场/逐实体保真/动作保真）、**inter-shot 实体一致（核心）**——用 DINOv2 embedding 相似度 + GroundingDINO 定位 + 多模态 LLM 逐实体保真与跨镜身份两两比对，共 51 个指标。
- **怎么接进 eval**：把「首次清晰出场做锚、后续每次比锚」这条度量思路搬进 `evals/journeys/`（现有 `j4-reference.mjs` 已做「参考图挂到视频节点槽」，天然可扩成「同一角色跨 N 镜身份保持」的离线任务）；embedding 相似度这条**离线指标先做，不接生产模型**。是本轮「最该动的事」的度量依据。

### DirectorBench — checkpoint 级诊断骨架
- **arxiv**：[2605.30090](https://arxiv.org/abs/2605.30090) · 2026-05-28 · repo + HF 公开
- **怎么接进 eval**：借它的 5 维（Script & Narrative / Visual / Audio / Cross-Modal / Stability）+ 40 checkpoint + 9 sub-metric 作 Nomi 内部诊断报告的骨架，尤其 transition 这个 sub-metric 直接对应 Nomi 时间轴 shot→shot 链。**只作诊断层，不作单一自动放行条件**（守 P3：全绿≠完成，仍需真实任务走查）。
